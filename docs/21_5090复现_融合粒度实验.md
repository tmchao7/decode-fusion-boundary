## 1. 这次要回答什么

> 融合/CUDA Graph 的**收益边界**是否随架构移动？

`docs/14` §1 记录了 A100 上的结论（**归档 `kernel.cu` 线**）：

```text
batch=1  megakernel E2E     2.241 ms/tok  vs cudagraph 2.944 ms/tok   -> 1.31x 胜
batch=1  megakernel device  1.89  ms/step vs cudagraph 0.74  ms/step  -> 慢 2.6x
cudagraph 0.74 ms/step = 1611 GB/s = 实测可达带宽(1699 GB/s) 的 95%
```

外部独立实现 AutoMegaKernel 在 **5090** 上自报：同精度 bf16 **输给** cuBLAS 1.24×，
只有 int8（fewer bytes）赢 1.19–1.23×（[20](20_方向重构_从dense到MoE融合kernel.md) §1.2）。
所以 5090 上"融合是否翻盘"不能靠转述外部数字回答，要么自己测，要么不写。

## 4. 预注册假设（取数之前写下）

### H-5090：5090 的 device 侧地板**更高**，因此融合的 device 劣势应收窄

- **推断**：5090 的权重墙是 **0.7645 ms/step**，A100 实测墙是 **0.702 ms/step**。
  5090 的规格带宽（1792）虽高于 A100（2039 的 83% 实测），但**实测可达带宽反而更低**
  （1559.2 < 1699）。所以在同一个 1.192 GB/step 的模型上，cuBLAS + CUDA Graph 的
  device 时间**不可能优于** A100 的 0.74 ms/step。
- **推论（可证伪）**：如果 megakernel 的 device 时间里有相当一部分是**与带宽无关的
  固定 per-step 成本**（launch 边界、barrier、drain），那么它在 0.7645 ms 的地板上
  占比更小 → `megakernel ÷ cudagraph` 的 device 倍数**应比 A100 归档线的 2.6× 更小**。
- **反证信号**：
  1. 实测 cudagraph 的 device ms/step **< 0.7645 ms** → 上述字节账/带宽账在 5090 上
     不成立。这是 **calibration finding**（`calibration_needed`），**不是 kernel 赢了**，
     必须先修模型（KV 读放大、权重字节口径）再谈结论；
  2. 实测 device 倍数 **≥ 2.6×** → 固定成本随 grid 变大而变大（170 SM vs 108 SM），
     "固定成本被高地板摊薄"这条机制被推翻，`docs/18` §4.1 的 launch/sync 界定也需要重标定。

### 沿用 `docs/18` §4.1 的粒度预测（不重新发明）

- `g ∈ {1,2,4,7,14,28}` 的指令数/层级/K 步**完全相同**（验证器已证）；
- 预测：device 侧「平坦到单调略差」，`g=28` 相对变化 **+4.7% ~ +15.7%**；
- **证伪阈值 15.7%**：超过即"边界成本可用 launch/sync 界定"被推翻；
  出现**谷底**则"bar 已把同样的边界串行化"被推翻。

> ⚠️ **基线的来源必须标出来**：`tools.bench_fusion_granularity` 的
> `--base-device-ms` 默认是**归档 A100 的 1.89 ms/step**（`docs/14` §1），
> **不是** 5090 的数字。它只决定预测表的绝对毫秒列；`g=28` 的相对阈值随基线缩放
> （1.89 → +15.7%，10.8 → +2.75%）。取数后必须按实测 `g=1` 重算这张表，
> 并把 `--base-device-ms-source` 写成实测来源。

## 6. 判读规则（先写下，避免事后编故事）

沿用 [14](14_融合粒度实验.md) §5：

- device 随 `g` **单调变差** → 粒度只通过 launch 开销起作用；
- 出现**谷底** → 分段拿到了更好的并行分解，下一步做 per-segment re-tiling；
- 曲线**几乎平坦** → launch 开销在该量级可忽略，粒度不是杠杆。

对 **H-5090**：

- 若 5090 上 `megakernel ÷ cudagraph` 的 device 倍数 **< 2.6×**：H-5090 未被否证，
  可写"融合的 device 劣势随架构收窄，机制是固定 per-step 成本被更高的带宽地摊薄"；
- 若 **≥ 2.6×**：H-5090 被否证，按 §4 的反证信号 2 处理；
- 若 cudagraph device < 0.7645 ms：**先怀疑口径**（`calibration_needed`），不要宣布 kernel 赢。

**对照的适用范围**：本页只做 5090 单机结论。**A100 一侧没有用当前 taskgraph 代码
重测**，因此 `docs/20` §9 第 1 步原文要的"A100 输 / 5090 赢 两机对照"在本页
**不成立**——本页给的是 5090 单机结果 + 归档 A100 的引用值。两机结论必须等
A100 用当前代码复测后才能写。
