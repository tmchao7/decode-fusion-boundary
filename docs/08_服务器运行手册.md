# 主线服务器运行手册

所有 GPU 命令统一写在 `SERVER_COMMANDS.txt`。主线 backend 只有
`torch-eager`、`torch-cudagraph`、`megakernel`；旧 kernel.cu 线不在当前命令面。

## 1. 环境

- GPU：A100-SXM4-80GB 为主要验证环境；
- CUDA：需要 NVIDIA driver、`nvcc`、CUDA-enabled PyTorch；
- Python：3.10–3.12；
- 模型：本地 Qwen3-0.6B，由 `NANOVLLM_MODEL_PATH` 指定；
- 架构：默认 `NANOVLLM_CUDA_ARCH=sm_80`。

```bash
bash setup_server.sh
source .venv/bin/activate
NANOVLLM_MODEL_PATH=$HOME/models/Qwen3-0.6B \
  python -m tools.verify_server_env --require-megakernel
```

## 2. RUN_MODE

| mode | 内容 |
|---|---|
| `model` | 下载/校验 Qwen3-0.6B |
| `verify` | 环境检查 |
| `build` | 只编译 task-graph extension |
| `correctness` | torch-eager vs Megakernel correctness gate |
| `benchmark` | torch-eager / torch-cudagraph / Megakernel 主表和 accounting |
| `taskgraph` | ABI、schedule、内核 batch/context 微基准 |
| `taskgraph-baseline` | correctness + 主表 + 四口径 accounting |
| `all` | build + correctness + benchmark |

最重要的第一条服务器命令：

```bash
RUN_MODE=taskgraph-baseline bash SERVER_COMMANDS.txt
```

## 3. Profiling 安全规则

不要对 cooperative kernel 使用 Nsight Compute (`ncu`)。kernel replay 会和
cooperative launch 冲突，可能卡住 GPU driver。使用 `nsys` 或
`tools/bench_taskgraph.py`。

## 4. 结果产物

主线命令会生成：

- `results/a100_build.log`；
- `results/a100_correctness_megakernel.json/.log`；
- `results/a100_performance.json/.md/.log`；
- `results/a100_account_breakdown.json/.md`；
- `results/taskgraph_baseline_correctness.json/.log`；
- `results/taskgraph_baseline.json/.md`；
- `results/taskgraph_baseline_breakdown.json/.md`。

## 5. 常见问题

- batch > 8：task graph 的 compile-time scratch/bar ceiling，应该在
  compatibility 阶段明确回退；
- prefill 请求：Megakernel decode-only，prefill 走 torch；
- sampling 请求：当前只支持 greedy；
- token 差异：使用 PASS/CASCADE/FAIL，不要把 BF16 reduction-order cascade
  当作自动失败；
- GPU 卡死：优先检查是否误用了 `ncu`。
