# 当前交接文档

> 更新日期：2026-09-28（服务器前收尾：KV 位置/槽位契约、测试结构拆分、文档对齐）

## 1. 当前状态

mainline 已收敛为一个公开 Megakernel backend：

```text
decode_backend="megakernel" -> task-graph kernel
```

旧的 `kernel.cu` persistent/WMMA/burst 实现已保存在 Git 分支
`codex/archive/frozen-kernel`，当前分支不再编译、导入或调度它。

当前主线状态：

- task-graph backend 已接入 `ModelRunner`；
- public backend 名称只有 `torch` 和 `megakernel`；
- task-graph 是 decode-only、greedy-only、single-card；
- `TG_MAX_BATCH=8`；
- shared weight packing 已从旧 decoder 拆到 `backends/megakernel/weights.py`；
- 当前工作区的 GPU 基线需要重新跑，不能沿用旧 kernel.cu 的性能数字；
- Phase 0 已加入 chunked-prefill budget、prefill/decode fairness 和 KV cache 运行时统计。

## 4. 不要做的事

1. 不要把旧 kernel.cu 恢复到 mainline；需要旧实现时切换到
   `codex/archive/frozen-kernel`。
2. 不要给 task graph 添加旧的 burst、WMMA/scalar batch 开关。
3. 不要对 cooperative kernel 使用 `ncu`；用 `nsys`。
4. 不要把 BF16 的全序列 token 不一致直接当作 correctness failure；使用
   PASS/CASCADE/FAIL。
5. 改 ABI、schedule 或 CUDA kernel 后，必须重新跑 ABI/schedule 测试和服务器
   correctness gate。

## 5. Phase 0 新增的系统能力

- `max_prefill_tokens_per_step=0` 保持历史行为；设置为正数后限制单轮
  prefill token 数；
- `prefill_decode_ratio=1` 在 waiting 和 running 同时存在时优先保护 decode
  ITL，再推进一个 prefill round；
- metrics summary 增加 `scheduler` 字段，包含 waiting/running、KV block
  使用量、peak usage、prefix cache hit/miss；
- batch=1 Megakernel 直接使用 sequence 的 host block table，TaskGraphDecoder
  复用持久 staging，避免每步构造临时 `[1, pages]` CUDA tensor。

## 6. 当前已知边界

- Qwen3-0.6B 固定结构；
- max model length 2048；
- task graph 每 step 一次 launch，没有旧的 no-sync burst；
- batch 8 以上必须显式回退；
- prefill 和 sampling 仍由 torch 路径负责。

## 7. 服务器前收尾（本轮，2026-09-28）

这一轮不碰 CUDA 算术，只把"服务器前能锁住的东西"锁住：

1. **KV 位置/槽位契约集中到 `engine/kv_layout.py`**。原来 prefill 的
   `slot_mapping` 计算内联在 `ModelRunner.prepare_prefill` 里（需要 torch 才能
   导入，因而无法在无 GPU 机器上验证）。抽取后 `ModelRunner`/`MegakernelBackend`
   都调用同一份实现，并有"与旧内联表达式逐值相同"的回归测试。
   锁定的恒等式：prefill positions = `[num_cached, num_cached+num_scheduled)`；
   first decode position = prompt_len；`cache_len = position + 1`；
   内核侧 `cache_len = cache_seqlens + 1` 由源码契约测试锁定。
2. **255/256/257 跨 block boundary 测试**（`test_kv_block_boundary.py`）：
   `num_blocks` / `last_block_num_tokens` / `slot_mapping` / `block_table` 长度，
   以及 decode 跨过 256 边界时会 `may_append` 一个新 block。
3. **BlockManager 真实行为测试**（`test_block_manager.py`）：prefix hit/miss、
   hash 链（第二个 block 不同不会误命中）、ref_count、freed-but-cached 复用、
   deallocate、peak_used_blocks、`can_append`/`may_append` 边界。
4. **测试结构拆分**：原 `tests/test_phase0_inference_system.py`（职责混杂、且用
   `SimpleNamespace` 桩掉真实依赖）拆成
   `test_scheduler_behavior` / `test_config_validation` / `test_phase0_contracts`，
   scheduler 行为测试改为驱动**真实** Scheduler/BlockManager/Sequence。
5. **KV pressure 语义确认**（`test_scheduler_behavior.py`）：`_schedule_decode`
   允许返回空 batch（不再 `assert`）；预占策略下 scheduler 继续推进；当 KV 池
   连一个序列都装不下时，`schedule()` 抛
   `RuntimeError("scheduler made no progress")` —— 这是容量错误，不是调度缺陷，
   错误信息明确且 `python -O` 不会吞掉它。
6. **无 torch 机器上 discovery 全绿**：7 个 task-graph CUDA 测试模块改成
   module-level `unittest.SkipTest`（只 catch `ModuleNotFoundError`，所以服务器上
   真正的 extension build 失败仍然响亮报错，不会被静默跳过）。
7. **删掉死 build 宏** `TG_NUM_BLOCKS` / `TG_MAX_BATCH`：kernel 与 `build.py` 里
   定义了但没人读（grid 用 `desc.num_sms`、batch 用 `desc.BS`），且有测试反向锁住
   它们的存在。现在加了反向锁：这两个宏不得回来。Python 侧的
   `taskgraph.TG_MAX_BATCH`（scratch/bar 容量）不变。
8. **文档对齐**：`docs/12` 不再引用已删除的 `RUN_MODE=taskgraph-perf`；
   `docs/11 §10` 重编号为 `§11` 并修正 ring buffer / 引擎集成 / attn_splits=2
   死锁三处过期结论；`docs/06`/`docs/07` 标注为已归档 `kernel.cu` 线的历史数据
   （其 `RUN_MODE=roofline|account` 已移除）；`docs/12 §2.5` 的编译命令行去掉
   `TG_NUM_BLOCKS`。并给 `test_server_commands.py` 增加了"当前文档不得宣传不存在
   的 RUN_MODE"的护栏（含负向验证）。
