# 当前交接文档

> 更新日期：2026-09-24

## 1. 当前状态

mainline 已收敛为一个公开 Megakernel backend：

```text
decode_backend="megakernel" -> task-graph kernel
```

旧的 `kernel.cu` persistent/WMMA/burst 实现已保存在 Git 分支
`codex/archive/frozen-kernel`，当前分支不再编译、导入或调度它。

当前主线状态：

- task-graph backend 已接入 `ModelRunner`；
- public backend 名称只有 `torch` 和 `megakernel`；
- task-graph 是 decode-only、greedy-only、single-card；
- `TG_MAX_BATCH=8`；
- shared weight packing 已从旧 decoder 拆到 `backends/megakernel/weights.py`；
- 当前工作区的 GPU 基线需要重新跑，不能沿用旧 kernel.cu 的性能数字。

## 2. 关键路径

```text
Config
  -> ModelRunner
       -> MegakernelBackend.compatibility()
       -> TaskGraphDecoder.decode_rows()

```

## 3. 第一优先级

在 A100 上执行：

```bash
RUN_MODE=taskgraph-baseline bash SERVER_COMMANDS.txt
```

需要回传：

- correctness log；
- torch-eager / torch-cudagraph / megakernel 主表；
- wall / GPU / host residual / GPU share accounting。

## 4. 不要做的事

1. 不要把旧 kernel.cu 恢复到 mainline；需要旧实现时切换到
   `codex/archive/frozen-kernel`。
2. 不要给 task graph 添加旧的 burst、WMMA/scalar batch 开关。
3. 不要对 cooperative kernel 使用 `ncu`；用 `nsys`。
4. 不要把 BF16 的全序列 token 不一致直接当作 correctness failure；使用
   PASS/CASCADE/FAIL。
5. 改 ABI、schedule 或 CUDA kernel 后，必须重新跑 ABI/schedule 测试和服务器
   correctness gate。

## 5. 当前已知边界

- Qwen3-0.6B 固定结构；
- max model length 2048；
- task graph 每 step 一次 launch，没有旧的 no-sync burst；
- batch 8 以上必须显式回退；
- prefill 和 sampling 仍由 torch 路径负责。
