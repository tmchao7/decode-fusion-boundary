# 基线、创新模块与当前边界

## 项目目标

本项目在 nano-vLLM 的基础上，针对 Qwen3-0.6B 的 autoregressive decode 阶段设计 CUDA Megakernel，目标是降低单 token 推理的 kernel launch 和中间激活访存开销，并通过可复现 benchmark 验证收益。

## Baseline

### PyTorch eager

配置：

```python
LLM(
    model_path,
    decode_backend="torch",
    enforce_eager=True,
)
```

这是最直接的标准 nano-vLLM 路径，用于观察没有 CUDA Graph 时的 host launch 和 GPU 执行开销。

### PyTorch CUDA Graph

配置：

```python
LLM(
    model_path,
    decode_backend="torch",
    enforce_eager=False,
)
```

nano-vLLM 会为不同 batch size capture CUDA Graph，并在 decode 时调用 `graph.replay()`。这是 Megakernel 的主要对照对象，因为它代表当前 nano-vLLM 已有的 decode 优化路径。

### HF/PyTorch reference

`benchmarks/megakernel_reference.py` 还保留了 Hugging Face PyTorch 与独立 Megakernel 的小型 reference benchmark，用于辅助 token-level correctness 和微基准分析。它不是 nano-vLLM 的主要 baseline。

## Megakernel 模块

Megakernel 已经作为 nano-vLLM 的一个 backend 集成：

```text
src/nanovllm/backends/megakernel/
├── backend.py       backend compatibility 与 fallback
├── build.py         CUDA extension 的 JIT build
├── model.py         权重打包、Decoder、KV cache 和 operator 调用
└── csrc/
    ├── kernel.cu
    └── torch_bindings.cpp
```

### `backend.py`

负责判断请求是否满足当前实现条件：

- Qwen3-0.6B 固定结构；
- BF16 权重；
- 单卡、单序列；
- greedy decode；
- `max_model_len <= 2048`；
- A100-class GPU。

不满足条件时回退标准 nano-vLLM，并在 metrics 中记录 fallback 原因。

### `kernel.cu`

当前融合了主要 transformer decode 计算：

```text
embedding
RMSNorm
QKV projection
Q/K normalization
RoPE
attention
O projection
residual
MLP
final RMSNorm
```

LM head/argmax 当前仍可能作为独立 kernel 执行。最终 kernel 数量、launch 时间和内存事务必须以 Nsight 结果为准。

### `torch_bindings.cpp`

把 CUDA 函数注册为 PyTorch operator，使 Python 侧可以调用：

```python
torch.ops.nanovllm_megakernel_C.decode
```

### `model.py`

从已经加载的 nano-vLLM 模型中取得权重视图并打包 pointer table，避免额外加载一份 Hugging Face 模型。当前 Decoder 支持独立 contiguous reference 模式和接收 nano-vLLM cache view 的 paged 模式；nano-vLLM 集成路径使用后者。

## 当前创新点

1. **decode 计算融合**：将多层 transformer decode 的主要算子放进 persistent/direct CUDA kernel，减少逐层 kernel launch。
2. **与 nano-vLLM backend 对接**：通过 `decode_backend="megakernel"` 选择后端，保留 PyTorch eager/CUDA Graph 作为对照和 fallback。
3. **可复现实验体系**：统一记录 TTFT、TPOT、ITL、E2E、吞吐、CUDA Event 时间、显存、NVML telemetry 和 correctness。
4. **面向硬件的编译入口**：通过 `NANOVLLM_CUDA_ARCH=sm_80` 为 A100 构建，V100 通过 `sm_70` 保留兼容性实验入口。
5. **失败不伪造收益**：Megakernel fallback 或 token correctness 失败时，benchmark 不计算 speedup。

## 必须如实说明的当前边界

当前版本还没有完成最终的 paged-KV 直连优化：

```text
当前：nano-vLLM paged KV cache + Megakernel private contiguous KV cache
目标：Megakernel 直接读写 nano-vLLM paged KV cache
```

因此当前结果可以证明：

- Megakernel 单序列 decode 的 correctness；
- 融合路径的端到端延迟和吞吐；
- 与 eager/CUDA Graph 的 A/B 差异；
- kernel launch 和 GPU 时间变化。

但在 A100 correctness、Nsight 和 batch 测试完成前，不能提前声称已经完成全部 paged KV、batch decode 或 V100 FP16 优化。

## 后续演进顺序

1. 直接读取 nano-vLLM paged KV cache；
2. 支持 `block_tables` 和多序列 `context_lens`；
3. 验证 batch decode 的 correctness；
4. 增加 V100 FP16 kernel path；
5. 再考虑 logits 输出、temperature sampling 和更多 Qwen 模型形状。
