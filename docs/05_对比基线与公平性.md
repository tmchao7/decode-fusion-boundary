# 主线对比基线与公平性

## 1. 当前主线的三条路径

| backend | 配置 | 角色 |
|---|---|---|
| `torch-eager` | `decode_backend="torch", enforce_eager=True` | host-bound 下界 |
| `torch-cudagraph` | `decode_backend="torch", enforce_eager=False` | 主要对照 |
| `megakernel` | `decode_backend="megakernel"` | task-graph 实现 |

旧的 `kernel.cu`、WMMA、burst 组合已经从 mainline 移除，保存在
`codex/archive/frozen-kernel`，不应出现在当前主表。

## 2. 公平性规则

1. batch 使用 CUDA Graph bucket（桶）边界或明确披露 padding；实现使用 `graph_bs` 桶列表。
2. task graph 是每个 decode step 一次 cooperative launch，不得和旧的
   no-sync burst 数字混在一起；
3. CUDA Graph 使用 FlashAttention/cuBLAS，而 task graph 的算子覆盖和
   reduction 顺序不同；task graph 的 attention/LM head 仍包含 scalar 部分，必须在报告中披露；
4. 每个结果区分 wall、纯 GPU、host residual、GPU share；
5. fallback 行不算 Megakernel 结果；
6. correctness 使用 PASS/CASCADE/FAIL，不要求 BF16 全序列逐 token 完全一致；
7. 主表默认只运行 `torch-eager,torch-cudagraph,megakernel`。

## 3. 主表 workload

```text
batch:        1, 2, 4, 8
prompt:       32, 512, 1920
max_tokens:   128
warmup/runs:  2/3
```

端到端行必须满足 `prompt + max_tokens <= 2048`；内核微基准可以单独测
context 2048。

## 4. 命令

```bash
RUN_MODE=taskgraph-baseline bash SERVER_COMMANDS.txt
```

服务器产物：

- `results/taskgraph_baseline_correctness.log`
- `results/taskgraph_baseline.md`
- `results/taskgraph_baseline_breakdown.md`
