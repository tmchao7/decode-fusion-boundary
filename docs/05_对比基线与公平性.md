# 主线对比基线与公平性

> **状态**：现行 —— 三条对比路径的口径与公平性规则。

## 1. 当前主线的三条路径

| backend | 配置 | 角色 |
|---|---|---|
| `torch-eager` | `decode_backend="torch", enforce_eager=True` | host-bound 下界 |
| `torch-cudagraph` | `decode_backend="torch", enforce_eager=False` | 主要对照 |
| `megakernel` | `decode_backend="megakernel"` | task-graph 实现 |

旧的 `kernel.cu`、WMMA、burst 组合已经从 mainline 移除，保存在
`codex/archive/frozen-kernel`，不应出现在当前主表。

## 2. 公平性规则

1. batch 使用 CUDA Graph bucket（桶）边界，或明确披露 padding —— 细则见 §6。
2. task graph 是每个 decode step 一次 cooperative launch，不得和旧的
   no-sync burst 数字混在一起；
3. CUDA Graph 使用 FlashAttention/cuBLAS，而 task graph 的算子覆盖和
   reduction 顺序不同；task graph 的 attention/LM head 仍包含 scalar 部分，必须在报告中披露；
4. 每个结果区分 wall、纯 GPU、host residual、GPU share；
5. fallback 行不算 Megakernel 结果；
6. correctness 使用 PASS/CASCADE/FAIL，不要求 BF16 全序列逐 token 完全一致；
7. 主表默认只运行 `torch-eager,torch-cudagraph,megakernel`。

## 3. 主表 workload

```text
batch:        1, 2, 4, 8          # 全部是 CUDA Graph 桶边界 → padding_factor = 1.0
prompt:       32, 512, 1920
max_tokens:   128
warmup/runs:  2/5                 # runs 从 3 提到 5（见 02 统计口径）
```

命令行以 `SERVER_COMMANDS.txt` 为准（`RUN_MODE=taskgraph-baseline`）；
本页只固定口径，不复制命令。

端到端行必须满足 `prompt + max_tokens <= 2048`；内核微基准可以单独测
context 2048。

## 6. cudagraph 的 batch 桶 padding（2026-09-28 补）

cudagraph 按**固定形状桶**replay：实际 batch 小于 replay 的桶时，多出来的行不写 KV
（`slot_mapping` 填 -1，因此**不影响正确性**），但**照做 GEMM**。这段时间落在 cudagraph
的每 token 数字上。桶表的唯一来源是 `src/nanovllm/engine/cudagraph_buckets.py`
（runner 侧即 `self.graph_bs`，选择用 `select_graph_bucket`），
每个结果点的 `cudagraph.padding_factor` 都记进 JSON。

两条规则：

1. **现行协议**（`benchmarks/compare.py` 用 `max_num_seqs == batch_size`）：
   batch 1/2/4/8 精确；batch ≥ 9 时 `max_bs` 自身被追加为桶 → 也是 1.0；
   **只有 batch 3/5/6/7 会 padding**（1.33x / 1.6x / 1.33x / 1.14x）。
   → 比较点只用 `{1,2,4,8}` 或 ≥16 的 16 倍数；用其它 batch 必须同时报 `padding_factor`。
2. **历史数据**：归档 crossover 扫描用的是 `max_num_seqs = max(batch_size, 32)`，
   其 cudagraph 行在 batch 3/5/6/7/10/17 上分别 replay 4/8/8/8/16/32，
   最坏 1.88x（batch 17–31 都 replay 32）。**因此 `docs/06`/`docs/07` 的 crossover 表
   在这一项上对 cudagraph 不利**，读表时按 factor 折算。

锁定测试：`tests/test_cudagraph_buckets.py`（含两种协议与"最坏 < 2x"的上界）。
