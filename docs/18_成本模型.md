# 解码步成本模型（结构式、可证伪）

> **状态**：现行 —— `docs/12` §1.2 波次模型的修正版；纯 CPU，不需要 GPU。

## 1. 它回答什么

三件事，按可信度从高到低：

1. **结构**：一步解码由多少个串行波、每波多少 K 步组成 —— 全部由 `schedule.py`
   的实际指令流推出，可本地复核；
2. **外样本预测**：用 108 SM 的**一个**实测点标定后，能否预测其它网格尺寸；
3. **预注册预测**：融合粒度 `g` 曲线的量级与证伪阈值 —— 在上机取数**之前**写下。

实现：`src/nanovllm/cost_model.py`；测试：`tests/test_cost_model.py`（20 项）。

## 2. 结构量：波 = 依赖层级

把解码后的指令流按**等待图深度**分层：同一层的指令互不依赖、可并发，层与层严格串行 ——
所以**一层就是一个波**。结论（BS=1，108 SM）：

| 量 | 值 | 说明 |
|---|---|---|
| 依赖层级（=串行波数） | **170** | `6 波/层 × 28 层 + LM_HEAD + LM_ARGMAX` |
| 每层同质性 | **每层恰好一个 opcode** | 代码里是**断言**（混层会 `RuntimeError`），不是假设 |
| LM_HEAD 波 | **13 轮** | 1357 条指令 ÷ 108 SM |
| 总 K 步 | **11612** | 见下表的构成 |
| 总指令 | 4522 | 与验证器/调度一致 |

**对 `docs/12` §1.2 的三处修正**（这是本模块相对原模型的实际增量）：

1. **197 波 → 170 波**：原计数把 `ATTN_COMBINE` 也算作一层，但它在 `attn_splits=1`
   下**不发射任何指令**。`attn_splits=2` 时它才存在，层级数变成 `7×28+2 = 198`。
2. **"每波 64 K 步"漏了轮数**：LM_HEAD 有 1357 条指令 = **13 轮**，原规则按 1 轮算，
   少算了 768 K 步。
3. **"所有 GEMM 的 K 都是 1024"不成立**：`FFN_DOWN` 收缩的是 `intermediate`(3072)，
   即 **192 K 步**，是 64 的 3 倍，出现在全部 28 层里。

K 步构成（108 SM）：

| 波 | K/指令 | 轮数 | K 步小计 |
|---|---|---|---|
| QKV_PROJ | 64 | 28 | 1792 |
| ATTN_DECODE | 1（ctx=1） | 28 | 28 |
| O_PROJ | 64 | 28 | 1792 |
| FFN_UPGATE_ACT | 64 | 28 | 1792 |
| **FFN_DOWN** | **192** | 28 | **5376** |
| ADD_RMSNORM | 0 | 28 | 0 |
| **LM_HEAD** | 64 | **13** | 832 |
| LM_ARGMAX | 0 | 1 | 0 |
| **合计** | | | **11612** |

## 3. 标定与外样本验证

用 **108 SM 的 10.8 ms/step**（`docs/12` 基线）标定 → **930 ns / K 步**。然后：

| 检查 | 模型预测 | 文档记录值 | 误差 |
|---|---|---|---|
| 108 SM（标定点，自洽） | 10.80 ms | 10.80 ms | 0 |
| **1 SM（外样本）** | **287.7 ms** | **275 ms** | **+4.6%** |
| 4 SM（对 Amdahl 插值） | 75.29 ms | 75.05 ms（`T(n)=8.3+267/n`） | **+0.3%** |

第二行是这条模型真正有价值的地方：**一个标定点 + 结构公式，预测另一个网格尺寸落在 5% 内**。
（4 SM 那行不是独立实测，而是与 `docs/12` §1.1 的两点拟合曲线插值一致 —— 两个独立推导
给出同一个数，仍是有意义的交叉验证。）

## 4. 预注册预测（上机前写下）

### 4.1 融合粒度 `g`

验证器已**证明**（`docs/17`）：`g ∈ {1,2,4,7,14,28}` 的指令数、依赖层级、K 步**完全相同**
（都 4522 / 170 / 11612）。所以模型里"粒度"只剩一个通道：**额外的 launch 边界**。

每个边界的成本夹在两个有据可查的量之间：

- 下界：一次 launch 边界 = 上一段的 drain + 新网格启动 ≈ **2 × grid sync**
  （实测 1.63 µs/次，`docs/07` §3.4）；
- 上界：cudagraph 线实测 host 残差 2.2–2.8 ms/step 摊到约 200 次 launch ≈ **11 µs/次**。

以归档 device 时间 **1.89 ms/step** 为基线：

| g | 1 | 2 | 4 | 7 | 14 | 28 |
|---|---|---|---|---|---|---|
| 下界 ms | 1.890 | 1.893 | 1.900 | 1.910 | 1.932 | **1.978** |
| 上界 ms | 1.890 | 1.901 | 1.923 | 1.956 | 2.033 | **2.187** |

**预测：g 曲线在 device 侧应该是"平坦到单调略差"，`g=28` 的相对变化在 +4.7% ~ +15.7%。**

**证伪阈值：若实测 `g=28` 的 device 时间相对 `g=1` 增加超过 15.7%**，则"边界成本可用
launch/sync 界定"被推翻 —— 那说明还有模型没表示的效应（L2 复用丢失、段尾 drain 比记账更贵），
本身就是结论。反之若出现**谷底**（某 `g>1` 明显更快），则"bar 已经把同样的边界串行化、
分段不带来额外并行"这个推理被推翻。

`tools/bench_fusion_granularity.py` 会在开跑前把这张表打印出来，并写进产物 JSON 的
`pre_registered_prediction` 字段。

### 4.2 另外两条可证伪预测

| 预测 | 依据 | 如果被推翻说明什么 |
|---|---|---|
| **BS 不变性**：BS 1→8 的 device 时间几乎不变（层级/K 步都不变） | 每波指令数在 108 SM 下仍 ≤ 1 轮 | 归档线 BS≥2 崩塌（`docs/07` §2.3）说明存在本模型未表示的机制 → **本模型只适用于 BS=1 的波串行区间** |
| **`attn_splits=2` 时间不变**：层级 170→198，但新增的 combine 波是归约、K 步为 0 | §2 构成表 | 若明显变化，说明 ATTN/combine 的成本远超"1 K 步"的近似 |

## 5. 局限（不要过度声称）

- **只解释波串行区间**：BS≥2 的并行分解失败、SM 空转、tile padding 都不在模型里。
- **ATTN 只算 1 K 步**：仅在 ctx=1 基线附近成立；长上下文需要另建 KV 项。
- **单点标定**：930 ns/K 步只属于产生它的 kernel 版本与形状；换 kernel 或换卡必须重标定。
- **L2 复用、段尾 drain、host 成本都不在 device 模型里** —— 4.1 的上下界就是为这三者留的余量。
- **跨线不可比**：`docs/archive/06/07` 的数字属于归档 `kernel.cu` 线；本模型标定在主线数字上，
  两线之间不要互相代入。
